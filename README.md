# Проект YaMDb

Проект YaMDb — это REST API сервис, собирающий отзывы пользователей на различные произведения: фильмы, книги и музыку. Сервис не хранит сами медиафайлы, его основная цель — предоставление платформы для оценивания и обсуждения произведений, а также формирование их рейтинга на основе оценок.

Документация проекта представлена в формате Redoc и доступна после запуска по адресу: `http://127.0.0.1:8000/redoc/`

## Инструкция по развертыванию проекта

Клонируйте репозиторий и перейдите в рабочую директорию:

```bash
git clone git@github.com:NablaBash/api-yamdb.git
cd api_yamdb
```

Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv venv
source venv/bin/activate
```

Установите зависимости из файла `requirements.txt`:

```bash
python3 -m pip install --upgrade pip
pip install -r requirements.txt
```

Выполните миграции и импортируйте начальные данные из CSV-файлов:

```bash
python3 manage.py migrate
python3 manage.py import_csv_data
```

Запустите локальный сервер разработки:

```bash
python3 manage.py runserver
```

## Пользователи и аутентификация

Аутентификация реализована с использованием JWT-токенов. Регистрация проходит в два этапа:
1. Пользователь передает `username` и `email`, после чего получает код подтверждения на указанный адрес (в режиме разработки письмо выводится в консоль).
2. Пользователь обменивает полученный код на JWT-токен.

### Права доступа (Роли)

* **Аноним** — доступен только просмотр списка произведений, категорий, жанров, отзывов и комментариев.
* **Аутентифицированный пользователь (user)** — доступно чтение, публикация отзывов и комментариев, выставление оценок, а также редактирование и удаление собственного контента.
* **Модератор (moderator)** — права пользователя, а также возможность редактировать и удалять любые отзывы и комментарии.
* **Администратор (admin)** — полные права на управление всем контентом, категориями, жанрами и пользователями системы.

## Примеры взаимодействия с API

В заголовке запросов, требующих аутентификации, необходимо передавать токен:
`Authorization: Bearer <токен>`

### 1. Регистрация и получение токена

**POST** `/api/v1/auth/signup/`
```json
{
    "email": "user@example.com",
    "username": "new_user"
}
```

**POST** `/api/v1/auth/token/`
```json
{
    "username": "new_user",
    "confirmation_code": "полученный_код"
}
```

### 2. Управление произведениями

Создание произведения (доступно только Администратору). Жанры и категория передаются в виде массива строк (slug):

**POST** `/api/v1/titles/`
```json
{
  "name": "Джентльмены",
  "year": 2019,
  "description": "Криминальная комедия Гая Ричи",
  "genre": ["action", "comedy"],
  "category": "movie"
}
```

Получение информации о произведении. В ответе жанры и категория возвращаются в виде объектов, а рейтинг рассчитывается автоматически:

**GET** `/api/v1/titles/{title_id}/`
```json
{
  "id": 1,
  "name": "Джентльмены",
  "year": 2019,
  "rating": 9,
  "description": "Криминальная комедия Гая Ричи",
  "genre": [
    {
      "name": "Боевик",
      "slug": "action"
    },
    {
      "name": "Комедия",
      "slug": "comedy"
    }
  ],
  "category": {
    "name": "Фильм",
    "slug": "movie"
  }
}
```

### 3. Отзывы и оценки

Один пользователь может оставить только один отзыв на конкретное произведение. Оценка (`score`) должна быть целым числом в диапазоне от 1 до 10.

**POST** `/api/v1/titles/{title_id}/reviews/`
```json
{
    "text": "Стильное кино с отличными диалогами и классическим почерком режиссера.",
    "score": 9
}
```

### 4. Комментарии к отзывам

Комментарии оставляются к конкретному отзыву на произведение.

**POST** `/api/v1/titles/{title_id}/reviews/{review_id}/comments/`
```json
{
    "text": "Абсолютно согласен, Колин Фаррелл сыграл великолепно."
}
```

## Управление данными (только для Администратора)

### Категории и жанры
Доступна полная CRUD-логика с поддержкой поиска по названию (`?search=`) и пагинацией.

* **GET / POST** `/api/v1/categories/`
* **DELETE** `/api/v1/categories/{slug}/`
* **GET / POST** `/api/v1/genres/`
* **DELETE** `/api/v1/genres/{slug}/`

### Пользователи
* **GET / POST** `/api/v1/users/` — список пользователей и создание администратором
* **GET / PATCH / DELETE** `/api/v1/users/{username}/` — управление профилем конкретного пользователя

Каждый пользователь может управлять своими данными по адресу `/api/v1/users/me/` (методы GET и PATCH, изменение собственной роли запрещено).
